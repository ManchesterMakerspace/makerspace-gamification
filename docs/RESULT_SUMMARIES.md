# Action results and short AI messaging

New kudos submissions send the giver one compact result DM after all requested destinations are terminal. If destinations remain unresolved 60 seconds after the first event, the giver receives a plain pending or partial result. Later delivery, failure, cancellation, or a successful operator retry edits the same DM. Recipient kudos and requested public posts preserve the original note. The actual once-only XP outcome is independent of delivery; a receipt never creates an award.

Positive XP, shop/rank/milestone results, and related unlocks share one private result per action and recipient. A reconciliation pass has a distinct action ID for each member; verified completion and review paths reuse their action ID through advancement. Completed transactions release results immediately. Separate actions remain separate. Corrections, consent/preferences, review requests, conversations, and notices requiring action retain immediate routes. Historical catch-up remains silent. Giver receipts never include recipient progress.

## Durable delivery

Summary owners use existing `ledger_evidence`, keyed by action, recipient, authorization class, and game consent generation. They record deduplicated event IDs, a fixed first-event-plus-60-seconds deadline, content revision, and Slack address. Lightweight `summary_flush` jobs reserve immutable `summary_delivery` facts and fingerprints in `ledger_outbox`. Python renders identities, destinations, decimal XP deduplicated by award ID, and verified milestones. Larger bursts use bounded factual lines and an achievements link instead of an oversized Slack message. The duplicate machine-style receipt block is removed.

A delivery lock serializes revisions. Workers suppress unchanged fingerprints and obsolete revisions, and merge Slack receipts into the current owner so events arriving during inference or posting survive. Prompt selections, full policy snapshots, exact projected policy, profiles, and composed text are saved before delivery and reused on retries. Stable post identifiers survive uncertain post retries, including recovery by a newer revision. Only Slack `message_not_found` permits replacement of a deleted parent; other update errors use normal retry handling. Slack/network timeouts after acceptance remain an uncertain external outcome; stable identifiers do not guarantee universal exactly-once Slack delivery.

Current identity and authorization are checked again before posts and edits. Game consent generations prevent old results from reviving after opt-out/rejoin. Peer-kudos receipts consistently use the participation exception while requiring eligible linked humans. Consolidated rank artwork waits for the parent without spending retry attempts, then uploads in its thread. Artwork with obsolete baked-in rank labels remains suppressed.

## Narration and requested guidance

Successful results may add one optional short sentence; pending and failure results stay plain. Qwen receives structured, verified facts and cannot change accounting, permissions, destinations, or member-authored content. The short receipt and summary profiles have a ten-second deadline, at most 128 output tokens, and one attempt. Invalid output or timeout omits the flourish and preserves the factual result. Thinking remains disabled in each request and the existing vLLM configuration.

Receipt policy projects `identity`, `authority`, `kudos`, `privacy`, and `response` from the validated matrix in canonical order. Game results use the same projection without `kudos`. Reservations retain the complete policy and its hash as well as the exact projection. Prompt sets remain separate and their inventory is not fixed. Delivery and status defaults each offer five paired choices: four primarily plain and one restrained System style, with recent-choice avoidance. Existing reservations retain their original inputs. Published overrides require explicit template-library adoption.

“Suggest a next step” is available on progress and consolidated game results. A request queues one caller-only response from existing progress deficits, blockers, and suggestions, with no tool round-trip. Guidance uses ten seconds and at most 256 tokens; failure returns the first applicable blocker or deterministic suggestion. Result requests reply in that DM's thread; progress-modal requests open a private DM. Requests remain tied to the caller's Slack identity and consent generation. Ordinary DM questions retain the existing bounded read-only conversation path.

Short generation uses a process-local circuit breaker per endpoint/model. Three consecutive transport failures open it for 60 seconds; one successful probe restores generation. A malformed response alone is not a transport outage. Diagnostics record generation duration and fallback codes, queue age, summary latency, and post/update counts without recording prompt or message bodies. `/ledger-admin metrics` exposes `short_generation` and `result_notifications` aggregate counts/timings; summary owner totals count actual posts/updates rather than cumulative revision snapshots.

Provider contracts: vLLM supports [request-level thinking overrides](https://docs.vllm.ai/en/latest/features/reasoning_outputs/#request-level-override), and Slack uploads accept [a thread timestamp](https://docs.slack.dev/reference/methods/files.completeUploadExternal/). Deployment pilots still need to verify these contracts against the configured image and live workspace.

## Deployment and verification

Deploy updated general workers together with `ledger-results` and `ledger-interactive`. These lanes handle summaries and conversations/guidance independently of routine delivery; none waits for inference startup. `ledger worker` starts all six queues locally. Run `ledger init` to apply the additional owned-evidence index; no collection or Mongo privilege is added. The 60-second cutoff determines aggregation readiness; Slack outages and rate limits can delay arrival.

New actions adopt consolidation. Existing reserved acknowledgement and receipt deliveries drain with their saved policy and text. Matrix version 21 makes humor optional and documents result/guidance limits. Operators using a Google Doc override must update the complete canonical matrix and explicitly reload it; repository updates do not publish external policy.

Run `python -m ledger.prompt_matrix`, `python -m ledger.prompt_library`, and `python -m pytest`. Local tests cover destination order, the cutoff and later edits, duplicate/unrelated events, XP and milestones, concurrency, restart/uncertain-post recovery, stable retry text, stale revisions, deleted parents, rate limits, AI fallbacks, consent cancellation, and threaded artwork. Separately pilot real Qwen latency/wording, Slack edits, and threaded uploads with deployment credentials.
